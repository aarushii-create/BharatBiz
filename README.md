# BharatBiz AI

BharatBiz AI is a multilingual, voice-first business decision assistant for Indian small retailers. It turns sales, inventory, and expense data into deterministic evidence, recommendations, and approval-gated purchase actions.

## Production deployment requirements

The application is structured to run as a single backend service with agent logic inside the existing Node.js architecture. It does not require Kubernetes, Docker orchestration, dedicated agent workers, GPU infrastructure, or self-hosted model infrastructure.

## Environment setup

Prerequisite: Node.js 20+

```bash
cp .env.example .env
npm install
```

Required environment variables are listed in [.env.example](.env.example). These include:

- app port and runtime mode
- production URL and allowed CORS origins
- session secret and auth configuration
- provider API keys via environment variables
- file/db location via environment variables
- optional API provider configuration

## Run locally

```bash
npm run dev
```

The dev command serves the Vite frontend on the configured frontend origin and runs the Express API with CORS and auth enabled.

## Production build and startup

```bash
npm run build:prod
npm run start:prod
```

The production startup command reads `.env` values, serves the built frontend assets, and exposes health endpoints and backend APIs without relying on localhost-only assumptions.

## Deployment configuration

This repo includes a deployable single-service config in [render.yaml](render.yaml) for a production-style web deployment. The app is designed to be deployed behind a normal web host without introducing separate agent services.

## Database and migration scripts

```bash
npm run db:migrate
```

The migration script validates and updates the app data structure safely. It does not run automatically during app startup.

Seed and test-data scripts are provided for manual use only and are intentionally not invoked by dev or production startup:

```bash
npm run db:seed:test-data
npm run db:seed:demo
```

These scripts are never executed automatically.

## Health and operations

- Health endpoint: `/api/health`
- System status endpoint: `/health`
- Request rate limiting, production logging, timeout-safe request handling, and error middleware are enabled in the backend
- Authentication and business data isolation remain enforced at the API layer

## Verify before submission

```bash
npm run lint
npm test
npm run build:prod
```

The automated suite covers deterministic business calculations, AI intent and tool selection, multilingual text and voice fallback, CSV validation, failure handling, edge cases, approval safety, audit trails, and product-flow integration.

## Product flow

1. Ask a business question in English, Hindi, Tamil, or Telugu.
2. Review deterministic evidence from sales, expenses, and inventory.
3. Inspect the recommendation and proposed purchase order.
4. Approve or reject the consequential action explicitly.
5. Review the resulting purchase order and audit trail.

## Submission notes

- Financial calculations are performed by deterministic services, not generated by the language layer.
- Unsupported questions and unavailable data return safe responses without fabricated metrics.
- Purchase orders are not committed until a human approves them.
- Provider credentials are configured via environment variables, not checked into source control.
- The app does not rely on hardcoded business IDs, demo users, or localhost-only endpoints in production deployment.
